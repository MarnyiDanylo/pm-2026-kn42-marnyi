# S-14. Автоматичні push-сповіщення: протокол перевірки критеріїв приймання

Дата: 2026-10-30 (Огляд Спринта 2).
Історія: `S-14`, 3 SP, Epic: Сповіщення.

## Потік перевірки

1. На серверному симуляторі API вноситься зміна до аудиторії однієї з пар (наприклад "ауд. 302 -> ауд. 415").
2. Фоновий воркер фіксує зміну та формує payload повідомлення з заголовком і текстом про заміну аудиторії.
3. Push-повідомлення доставляється на тестовий пристрій клієнта за 2,5 хвилини (норма до 10 хвилин).
4. Якщо в системних дозволах операційної системи сповіщення вимкнено, при черговому запуску застосунку користувачеві виводиться діалогове вікно з пропозицією активувати дозвіл для отримання термінових змін.
